## 2. Connection Test

### 2.1 输入和所有权

支持测试当前未保存的 draft；先得到 canonical validated draft，再建立独立 TestRun owner。测试不能覆盖生产 TunnelSlot 的健康，也不能以测试需要为理由保存草稿密码到永久 keyring。临时敏感输入仅存于测试 owner，结束/取消释放。

每个测试携带 TestRunId、editor session、配置摘要/版本、开始时间，结果分阶段返回。切换草稿后旧结果标为不适用于新配置。并发测试受全局 handshake 预算限制，排队可取消。

### 2.2 结果层次

| 检查 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 配置验证 | 字段/引用/策略可表达 | 当前网络与端口可用 |
| 本地 bind 预检 | 检查时能绑定或已有本程序 owner | 保存后启动时必定可绑定；存在 TOCTOU |
| SSH 链测试 | 当时每跳信任、认证与 session ping | 目的业务服务健康 |
| 目标 TCP 测试 | 指定路径下可建立目标 TCP 连接 | 数据库/HTTP 等应用语义正确 |
| Remote 注册测试 | 该测试实际成功注册的端点 | 用 port 0 成功就能证明固定业务端口空闲 |

Local/Dynamic 正在运行的本程序 listener 不应被当作外部占用，更不能测试时抢占它。Remote 默认仅测试 SSH 链，绑定测试需用户明确选择，使用独立安全 registration 并清理；清理未确认要如实显示。

默认不发送任意业务 payload、不访问公共测试网站、不执行远端命令。SOCKS 测试目标由用户明确选择或使用本地测试环境，不能为测量速率偷跑外网流量。

### 2.3 展示

逐跳显示 Connecting / Authenticating / Verified / Failed 与安全原因；测试成功给时间戳和“仅代表本次测试”。Test 可取消，UI 关闭不丢失 core 对资源的清理责任。

## 3. Traffic Monitor

### 3.1 计数定义

upload/download 以用户本机端的流量方向定义。Remote 模式尤其要核对方向，不能因为调用 relay 的参数顺序改变而把 UI 箭头标反。业务 payload 字节统计与 SSH 协议/加密开销分开，界面称“转发数据量”，不声称是网卡全部字节。

当前计数器创建在 worker 内，会随 attempt 重建。整改后累计计数 owner 与 TunnelId 的本次应用运行关联，跨自动重连继续累加。历史窗口仅保留最近 120 秒；累计何时清零必须固定为应用重启、显式重置或删除，不能随机因编辑备注清零。[S07](13_SOURCE_INDEX.md#s07)、[S09](13_SOURCE_INDEX.md#s09)、[S26](13_SOURCE_INDEX.md#s26)

活跃连接由 RAII guard 管理。pending handshake/open 与 active relay 分开展示或在诊断中分开统计，不能把排队连接冒充已可用连接。

### 3.2 采样和开关

全局采样器以 1 Hz 读取原子计数差值，按真实单调时钟间隔计算 B/s；系统睡眠、阻塞或错过 tick 不把巨大累计差全部当作恰好一秒的瞬时流量。恢复后缺失区间标记断点或使用实际间隔。

每隧道 120 个固定容量样本，不存无限 Vec，不按 packet 发布 UI 事件。聚合全局流量时每隧道计一次，不按 hop 再加一次。关闭 Traffic Monitor 后停止历史采样与曲线重绘，可保留成本很低的累计/活跃计数；设置帮助中明确此含义。

计数采用一致的 session/reset epoch，避免读取跨 reset 的差值下溢。原子独立读取不保证上传/下载同一纳秒一致，UI 接受采样近似；不为此给热路径加全局锁。

### 3.3 验收

本地受控双向传输，验证累计只统计实际写出的 bytes；半关闭、取消、错误仍释放 active guard。跨 100 次重连计数不倒退。暂停监控不影响业务数据。不同模式方向正确。大量停止定义不分配无限采样任务。

## 4. Delete / Duplicate / Search

删除运行隧道先走 Stop 生命周期，确认资源结束或显示清理异常，再提交删除配置；不能先在 UI 删行、后台却继续转发。多项删除用共同操作上下文和版本检查。

删除与保存提交之间崩溃时，启动依据完整磁盘配置恢复，并遵循其启动策略；不能承诺“只存在内存里的删除意图”跨崩溃保留。若要求崩溃后删除请求必定生效，需进入 05 的事务记录协议，而不是 UI 先隐藏。

Duplicate 新建稳定 ID、可识别的新名称，默认 auto_start=false，不立即运行；检测端口冲突并要求修改/确认，不复用 runtime owner、history 或 generation。复制 Tunnel 复用明确选择的 HostId，不把密码读出再写一次。

搜索/筛选在本地已加载的有界配置集合中完成，必要时缓存规范化检索键并在 revision 变化时失效。不要为 1024 条配置引入数据库或全文搜索服务。

## 5. Groups、RTT 与诊断

Group 拖动排序保存 sort_order，经 canonical revision 更新。上下按钮是键盘等价入口，保留。隧道移动分组只改元数据，不重启 SSH；手动停止的 auto-start 项不得因分组保存复活。

RTT 排序使用最近有效数据，并显示采样时间；过期数据标记 stale。多个可选主机的连接测试可以帮助用户选择，但默认不自动热切换生产链，因为现存 TCP 流不能自动迁移。不要复制一项“最快节点”按钮，却隐去多跳认证和信任差异。

诊断应能区分 SSH 链健康和目标端口失败。收集的本地诊断包限配置摘要、版本、脱敏日志与资源采样，不含 SecretRef 的可移植复用信息、密码、私钥和 SSH payload。

## 6. 导入和凭据生命周期

完整导入契约在 05。关键是“解析成功不等于连接行为等价”。无法表达的 ProxyJump、HostKeyAlias、UserKnownHostsFile、IdentityFile 列表等必须显示处理状态，敏感差异不可静默降级。

密码修改提供 Keep/Replace/Remove。旧凭据删除基于当前配置、保留备份、事务以及仍运行 owner 的引用集合，不是替换后立刻清空。缺凭据是可见待配置状态，不用一个看似有效的 `pending` 引用掩盖导入后必定失败。

## 7. 安全的 SSH 命令导入（本轮建议增量）

只做 **字符串解析 → 中间模型 → 预览 → canonical 校验 → 用户保存**，产品运行时不调用 shell、ssh.exe 或任何外部隧道子进程。

建议支持 `ssh` 命令名、`user@host`、`-p`、`-l`、`-i`、`-J`、多个 `-L`/`-R`/`-D` 以及它们的分离/紧贴参数形式。同一条命令包含多个转发时生成多条 Tunnel 定义，共用对应主机定义；这是解析能力，不要求立即引入共享 SSH session 池。

IPv6 方括号、带空格路径与 Windows/POSIX 引号规则分别定义。提供粘贴格式选择或清楚的自动检测失败提示，不把两种 shell 规则拼成不可靠的万能 lexer。

任何 ProxyCommand、shell substitution、重定向、管道、脚本和未知 `-o` 项都不执行。影响连接/安全的未知项阻止直接标 Ready；普通无法映射项以预览警告明确展示。不能执行 `ssh -G` 作为生产导入的“方便实现”，测试环境对照可独立使用受控 OpenSSH fixture。

不得自动展开任意环境变量、执行远端命令或从历史中猜密码。预览沿用外部配置的信任、暴露和自动启动保护。导入命令被存入诊断时需脱敏，默认不保留完整原始字符串。

## 8. 完成定义

每项功能必须包含领域语义、core 接线、UI、失败状态、资源释放和测试。不能以“结构体里有字段”“按钮能点击”“测试中注入 mock 成功”判定产品功能已完成。

本章新增功能的实施仍依赖 03/05 的稳定状态和配置协议。界面先用 fixtures 开发可以，但必须在发布前全部换成真实适配器；任何 fixture 入口只限测试或明确的 demo binary。
