# 06 · UI 设计系统

## 1. 设计方向

**紧凑、清楚、安静的原生隧道工作台。** 参考 Loris 的任务组织方式，采用原创的 Zed 式信息密度、窄边界、克制高亮与工具型组件。不复制品牌、图标或源码，不做浏览器管理后台，也不做 macOS 窗口装饰。

当前审阅来自 workspace.rs 的实际结构，没有运行并观看当前 Windows 界面。本章是新的设计规格，不是已经渲染完成的视觉稿。外部组件能力参考 [E02](13_SOURCE_INDEX.md#e02)、[E03](13_SOURCE_INDEX.md#e03)、[E04](13_SOURCE_INDEX.md#e04)，生产接入必须核对固定 `gpui-kit =0.6.6`。

主界面首先回答四件事：哪条隧道需要处理、实际连接到哪里、当前能做什么、操作是否完成。配色服务于这四件事，而不是相反。

## 2. 明确不要做什么

不要大面积渐变、背景图片、玻璃模糊、大阴影、卡片套卡片或巨大的状态数字。不要每条隧道使用不同颜色、每个动作都做 primary button、每个表格单元格都加边框。不要为了少写布局，把 Select、Switch、Radio、菜单全部替换成长按钮列表。

不要在 Overview 显示虚构曲线或随机示例延迟。生产数据缺失时显示“尚无数据”，不能用演示数据填充。不要把错误作为页面底部很长的红色字符串，让用户自己定位哪条隧道出问题。

## 3. 空间与布局

尺寸均为逻辑像素，随 DPI 缩放，不是物理屏幕像素。

| 区域 | 默认值 | 规则 |
|---|---:|---|
| 初始窗口 | 1180 × 760 | 沿用当前尺寸基线；首次打开限制在工作区内 |
| 首选最小窗口 | 920 × 600 | 工作区更小时改用紧凑布局，不把窗口强制撑出屏幕 |
| 导航栏 | 196 | 可折叠到 52；不是任意可拖动的大空栏 |
| 顶部工具栏 | 48 | 页面标题、搜索、筛选与一个主要动作 |
| 页面内边距 | 20 | 窄窗口 16，避免每层重复叠加 padding |
| 列表标题行 | 32 | 表头固定，底部 1px 分隔 |
| 默认隧道行 | 52 | 名称一行、规则摘要一行 |
| 紧凑隧道行 | 40 | 可选设置；仍保留可点击目标和可读字级 |
| 详情侧栏 | 336 | 允许 320–380；不是始终占满右半屏 |
| 状态栏 | 24 | 核心状态、当前后台任务、必要的全局速率 |
| 编辑面板 | 640 | 宽屏侧面板；窄屏变为主区域完整编辑页 |
| 控件高度 | 32 | 少量表格内操作 28；不把全部按钮缩到难点击 |

### 布局断点

宽度足够容纳“导航 + 列表最小宽度 + 详情”时采用三栏；否则详情作为有返回入口的抽屉/主内容面板打开。以实际内容宽度为判断依据，不只按屏幕分辨率猜测。

窄窗口优先隐藏“流量历史”和次要认证摘要列，保留名称、规则、状态、主要操作。RTT 可移入状态单元格或详情。横向滚动是最后方案，不能让 Start/Stop 被挤到屏外。

在 1920×1080 屏幕的 200% DPI 环境，逻辑工作区可能小于首选最小窗口。首次窗口定位、恢复旧尺寸和系统任务栏均要纳入 work-area 限制。

窗口标题栏先使用稳定的原生方案。只有 GPUI Kit 固定版本已验证的原生标题栏集成才可用于定制；不要为追求外观引入新的拖动、最大化和 DPI 缺陷。

## 4. 颜色令牌

以下是**拟定的起始配色**。实现后必须在实际字体、显示缩放和禁用状态下检查对比度；不是视觉验收已经通过。

| 语义令牌 | 深色 | 浅色 | 用途 |
|---|---|---|---|
| `surface.app` | `#181B20` | `#F7F8FA` | 主背景 |
| `surface.sidebar` | `#14171C` | `#EEF1F5` | 导航与分组 |
| `surface.panel` | `#1D2128` | `#FFFFFF` | 列表、详情、普通表单 |
| `surface.raised` | `#252B34` | `#F0F3F7` | 菜单、浮层、hover |
| `border.subtle` | `#343C49` | `#D6DDE6` | 装饰性分隔 |
| `border.control` | `#657285` | `#7A8798` | 必须清楚辨识的输入/控件边界 |
| `text.primary` | `#E6EAF0` | `#222A35` | 名称、输入、状态 |
| `text.secondary` | `#A9B2C0` | `#526072` | 路由、副标题 |
| `text.muted` | `#909BAD` | `#627286` | 次要说明；不用于隐藏重要错误 |
| `accent.fg` | `#82B4FF` | `#2468C3` | 焦点、链接、选中指示 |
| `selection.bg` | `#263B57` | `#DCE9FA` | 当前选中行 |
| `success.fg` | `#74C69D` | `#1F744E` | 健康证据已满足 |
| `warning.fg` | `#E7BB69` | `#8C5C08` | 降级、等待用户动作 |
| `danger.fg` | `#F08A8A` | `#BA3038` | 阻断和破坏性操作 |

普通表格不铺整行绿色/红色。状态颜色只用于小图标、状态文字或窄边标记；选中背景始终保持统一。只读、未测量、停止不能使用与成功相同的绿色。

primary button 的背景与前景单独成对定义。不能直接拿 `accent.fg` 作为浅色背景再配白字，而不验证对比度。常规文本以对比度至少 4.5:1 为设计门槛，关键非文本状态边界/焦点以至少 3:1 为门槛；最终仍需按实际组合验证，不能因有令牌表就宣称完整无障碍认证。

页面代码不得散落十六进制颜色。`theme.rs` 统一映射产品令牌到 GPUI Kit 主题角色，`metrics.rs` 管尺寸。浅色/深色/System 切换必须立即生效，不重启隧道。选择 System 时只订阅一次系统变化，由应用所有者管理。

## 5. 字体、图标与间距

正文使用 Windows 系统 UI 字体及系统中文回退，建议正文 14、表格数据 13、次要说明 12、区块标题 14 semibold、页面标题 18。端点、端口、指纹和数值用系统等宽字体；不嵌入庞大自带字体包。字体文件不属于本次交付。

图标使用一套现有组件兼容的线性图标，16 为默认，20 用于页面导航。没有可靠图标时保留文字，不用 emoji 或 Unicode 箭头代替所有控件。图标按钮有 tooltip 与可访问名称，不依赖悬停才能发现主要操作。

间距使用 4/8/12/16/20/24，普通圆角 4，菜单/面板 6。禁止多个近似但不同的尺寸在不同页面随意出现。名称与状态较重，路径和说明较轻；不要整页同样的字号和字重。

长名称单行省略，完整内容能在详情/tooltip 查看。IP、指纹和错误复制必须复制原始完整值，不复制被截断的展示文本。

## 6. 组件职责

| 组件 | 所属层 | 必须解决的问题 |
|---|---|---|
| `AppShell` | 应用 UI | 导航、当前页面、窗口级焦点与 overlay 栈 |
| `TunnelTable` | 产品组合 | 虚拟行、稳定选择、排序筛选、行操作 |
| `TunnelStatus` | 产品组合 | 快照 → 图标/文案；不判断 socket 健康 |
| `RouteSummary` | 产品组合 | 模式方向、本地/远端端点与多跳摘要 |
| `TunnelInspector` | 产品组合 | 独立状态维度、可执行诊断、真实数据 |
| `HostPicker` | 产品组合 | 搜索、已选状态、冲突/无效主机提示 |
| `JumpChainEditor` | 产品组合 | 顺序、最终主机、拖动与键盘等价动作 |
| `TrafficSparkline` | 轻量绘制 | 有界样本、断点、可见区域内绘制 |
| `OperationFeedback` | 产品组合 | accepted/in-progress/committed-warning/failed |
| Input/Select/Switch/Dialog/Menu/Table | GPUI Kit | 复用现有基础交互，避免重复造轮子 |

这些是建议的产品边界，不是要求为每一层再加一层 trait 或 generic wrapper。优先用组合和窄数据接口。原生 Windows 生命周期与后台运行时不进入页面组件。

## 7. 所有状态都要设计

状态至少有停止、排队、连接、认证、等待信任、建立转发、健康、降级、退避、阻断、正在停止。区分 `desired=Running` 与 `observed=Blocked`，不能把后者画成关闭的开关，让人误以为端口已经释放。

运行中的 spinner 只用于真实短期工作；长时间重连显示下次重试时间与原因，不永远转圈。弱动效只改变 hover、焦点和面板出现，约 100–150ms；支持减少动效。静止页面不应存在持续 60Hz 的无效动画。

健康必须是文本+图标，不仅颜色；例如“健康 · 38 ms”“等待主机密钥确认”“重连中 · 3 秒后重试”。停止与尚未测量显示破折省略符或“未测量”，不要显示 `0 ms`。

## 8. 渲染与资源边界

InputState、FocusHandle、列表/滚动状态和订阅在 owner 创建时建立，不在 render 中重建。每行用 TunnelId/HostId 作为稳定 key，不能用排序后的 index 存编辑对象。

用 GPUI Kit 固定版本支持的虚拟化表格/列表；当前 25 条分页不是“无界渲染漏洞”，但可替换为更适合桌面操作的虚拟滚动。隐藏页面暂停非必要 UI 更新，不暂停核心隧道维护。

曲线复用 120 样本有界缓冲，每秒最多采样/呈现一次；未显示的详情不分配绘制工作。断开窗口后释放 UI 实体及订阅，应用 runtime 继续持有隧道。不要用昂贵隐藏窗口保活，更不要调用 Working Set trimming 装作省内存。

## 9. 视觉验收

同一固定测试数据集分别覆盖深/浅主题、100/125/150/200% DPI、默认和紧凑窗口。截图必须来自实际应用，不能用网页原型代替最终截图。

检查列对齐、数字对齐、长名称、省略与复制、按钮对比、禁用状态、焦点圈、错误阅读、表单滚动、保存栏固定、弹窗层级、菜单不越屏。检查 0/1/25/1000 条数据和 16 跳编辑。至少让一位未读源码的人独立完成“新建、连通、查错、停止、导入”五条流程。

本章只有设计目标。完成定义与测试证据在 [10](10_TESTS_AND_RELEASE.md) 和 [14](14_ACCEPTANCE_CHECKLIST.md)。
